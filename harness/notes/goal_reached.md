# `goal_reached`: актуальность и адекватность

## Что это в `kbshff`

`stop_reason: goal_reached` ставит цикл в [`src/agent/loop/engine.rs`](../../../src/agent/loop/engine.rs),
когда модель вернула `done=true`. Это **конец петли**, не приёмка задачи.

Другие значения: `limit_reached` (итерации/токены/время/бюджет), `error`
(сбой раннера). Процесс при `goal_reached` и `limit_reached` выходит с кодом 0
([CONTRACT.md](../../../CONTRACT.md)).

Имя историческое: системный промпт говорит «when the goal is achieved, return
done=true». Модель сама объявляет цель достигнутой. Раннер **не** сверяет
артефакты, договорённости и needles.

## Насколько актуально

Как сигнал оркестратору «агент сам остановился» — **да, нужен**.
Нужно отличать:

| Сигнал | Смысл |
| --- | --- |
| `error` | раннер сломался |
| `limit_reached` | не дописал, упёрся в лимит |
| `goal_reached` | модель сказала done |

Без этого трёхзначного enum нельзя понять, продолжать ли конвейер.

Как критерий **pass задачи 1c-live** — **нет, не адекватен**. Прогон
`20260817-183746`: все четыре стадии `goal_reached`, скоринг FAIL (другое имя
теста). `done=true` после «я написал тесты» ≠ литералы банка.

`blocked` при `done=true` тоже становится `goal_reached`. CLI не отличает
«сделал» от «отказался» от «ошибочно решил, что сделал».

## Что меняем в 1c-live (не ломая контракт CLI)

Контракт `kbshff` (`StopReason`) не переименовываем: это breaking change для
всех оркестраторов. В copy-unit:

- Банк **не** кладёт `expect.stop_reason: goal_reached` рядом с needles.
- Скоринг: незавершённый цикл (`error` / `limit_reached`) → fail стадии.
  `goal_reached` **не даёт** pass; pass = agreements + артефакты + needles.
- В NOTES поле называется `agent_stop`, не «цель достигнута».

Переименование в CLI вроде `done_declared` — отдельный breaking RFC, не этот
workflow.

## Как читать отчёт

1. `agent_stop=goal_reached` — петля закрылась.
2. `pass=true` — контракт стадии (файлы, литералы) сошёлся.
3. Оба сразу — редкость, пока модель не держит agreements.
